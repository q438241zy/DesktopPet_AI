# 走路與 Q 版積木動作修整

本輪使用內建 image_gen，以各角色、畫風與服裝自己的舊行走圖為身份參考，生成 72 張十二幀行走圖，以及 24 張 Q 版十二姿勢積木圖。完整提示詞在 `prompts/`；每次生成輸出的原始檔位置與修訂號在 `results/`。`manifest.json` 記錄最終採用的圖、SHA-256、透明比例及裁切座標。生成圖片保持原始像素與透明通道，沒有程式重畫、補色或放大。

行走採右向側面、頭髮及尾巴拖在後方，以接地、下沉、腿部交錯、抬升、另一腳接地組成步態。每幀 80 毫秒，共 960 毫秒。程式按實際位移推進腳步，碰到邊界先站穩 160 毫秒再轉向。人物以本服裝待機高度校準；裁切區寬高變化不再改變像素縮放倍率，避免腿部姿勢造成身體忽大忽小。

Q 版積木分為伸手、握住、拿起、移向塔頂、放下及鬆手；方塊與手畫在同一圖內，禁止額外疊加浮動積木。十二姿勢播放一次，完成塔保留至互動結束。DeepSeek 原裝採最初組合圖的後十二格，其餘使用各自獨立積木圖。

驗收腳本 `tools/install-motion-polish.py` 檢查 RGBA、透明區、連通輪廓、畫格排列、越界及重複影格。少數生成結果採 4×3 排列，清單明確記錄實際排列；角色黏在相鄰畫格的圖必須重新生成，不能用錯誤分格掩蓋。矩形範圍可能含有鄰格的碎片，`isolateCells` 在讀圖時依連通輪廓分配畫格，只顯示屬於本格的像素，保留邊緣透明度與分離的方塊，不修改原圖。`--verify-polish` 從真正的 WPF 渲染器檢查 72 套步態、24 套積木及食物／槌子是否重複，並輸出逐幀對照圖；還以交疊矩形的合成測試確認輪廓裁切及原尺寸像素。

Q 版原裝已有碗匙的早餐圖與已有槌子的敲打圖標為 `bakedProps`。零食改用原有餵食圖。其餘外觀敲打共用 Q 版畫稿內的小槌子，命中只做一次輕微反應。沒有專用進食圖的服裝仍在動作清單如實標記。

本輪 UI 使用程式繪製的奶油白、暖粉與杏桃雲朵、腮紅笑臉及蝴蝶結，圖示保持向量清晰度。Demo 使用 560×680 原尺寸、每秒 25 次取樣的無損 WebP，保存在 HTML 同目錄的 frames 資料夾，按當前動作預載解碼，避免將數百 MB 圖像直接嵌入網頁；瀏覽器散步有獨立循環時鐘，避免移動繼續而腳步停止。
