# 角色包格式 v1

一个角色包是包含 `pet.json` 与其引用图片的目录。导入时只复制清单和被引用的图片，不执行任何代码，也不会复制账号文件。

```json
{
  "version": 1,
  "id": "my-pet",
  "name": "我的伙伴",
  "accent": "#D59477",
  "category": "chibi",
  "description": "角色介绍",
  "demo": false,
  "atlas": { "file": "atlas.png", "columns": 3, "rows": 2 },
  "dizzy": { "file": "dizzy.png", "columns": 1, "rows": 1 },
  "motions": {
    "walk": { "file": "walk.webp", "columns": 3, "rows": 2, "facing": "right", "frameMs": [160,160,160,160,160,160] }
  },
  "outfits": {
    "wedding": {
      "name": "婚纱",
      "idle": { "file": "wedding.png", "columns": 1, "rows": 1 },
      "motions": {}
    }
  }
}
```

六姿势图集按行排列：悠闲、开心、摸摸、睡眠、晕倒、难过。标准为 1536×1024，每格 512×512，身体中心 x=256、落地脚底 y=448。各动作必须共用比例和基线。单张图应明确写 `columns: 1, rows: 1`。

`category` 为 `chibi`（Q版）、`3d`（3D版）、`adult`（真人版），省略时兼容旧包，归入 Q版。`adult` 保留旧清单与存档兼容，仅界面名称改为“真人版”。这是画风分类，不改变渲染方式；当前均使用二维透明图。`demo: true` 会显示预览标记：当前服装有多帧行走时为“行走预览”，否则为“静态立绘”。同一 `family` 的分类切换会同步应用到桌面，并保留目标形象支持的同名服装。

可选字段 `family` 标识同一角色的不同画风，例如 `deepseek-3d` 和 `deepseek-adult` 的 `family` 均为 `whale`。省略时使用角色自身 ID。内置风格预览按角色系列对应三种画风；导入角色仍可在对应分类单独使用。

每个图集可指定原始朝向 `facing: "right"` 或 `"left"`，默认朝右。行走时按移动方向与原画朝向一起计算水平翻转；不要把左右朝向混在同一组帧内。程序按每帧可见像素的底边对齐桌面地面，避免额外浮动。行走必须提供至少两帧的 walk 动作；单张静态姿势不能触发桌面散步。

`motions`、`outfits` 和 `dizzy` 可省略。不要在清单引用尚未画好的图片。`frameMs` 若提供，长度必须等于 `frames` 序列长度（未指定序列时等于格数），每项 40–5000 毫秒；省略时每格 240 毫秒。动画名称包括 eat、feed、chat、bonk、farewell、walk、angry、headpat、curl、ball-hit、ball-miss、pickup、think、jump、peek、shaken、shaken-strong，以及可逐步补齐的 meal、pounce、poke、tickle、kick。

动作选择顺序是当前服装同名动作、当前服装的语义回退动作、当前服装基本姿势。正餐回退吃饭、扑抱回退聊天、戳脸回退摸头、挠痒和踢积木回退跳跃。选中泳装或婚纱后，任何动作都不会借用原装图。原装只在选择原装或存档服装不存在时使用。

服装的 `idle` 可以是单格立绘或姿势图集；缺少专用动作时保持这张图的对应姿势。旧包只有服装动作、没有 `idle` 时，使用其第一组动作的首帧作为静止图。服装必须至少提供 `idle` 或一组动作，不能是空条目。Q版、3D版、真人版使用相同的规则。只有当前服装自己的 `walk` 至少有两帧时才能散步，不能从其他服装借用行走能力。

内置八位角色的 3D 与真人版使用各自服饰的专用进食与日常互动图集；聊天、发呆、跳跃、蜷起、睡眠、积木、提起、球命中和落空均有独立画稿。触摸和真人舞蹈继续使用程序骨骼；舞蹈只向真人版开放。骨骼依赖内置立绘的正面姿势与身体位置，不能自动适配任意导入图；自定义角色应提供自己的动作素材。

导入器拒绝重复角色 ID、绝对路径、上级目录引用、文件流、符号链接、目录联接和非图片文件。清单最多 256 KB，单图最多 24 MB、边长最多 6144 像素，全部图片最多 180 MB。图片必须可解码；未设置 `cells` 时，尺寸必须能均分到格子。ID 为 1–48 位小写字母、数字和连字符。

原 Character_Generator 的成果目录可直接导入。导入器按 P01、P06、P10、P11、P17、P23、P24 与 E01/E02/E03 识别基本姿势；未识别的组合仍保留在原成果目录，不会自动塞进不对应的互动。它们是静态姿势，若希望真正逐帧动作，请使用上面的图集清单。

## 逐帧道具接触

1.2.0-preview.6 支持在同一图集中按 `frames` 数组选择和重复姿势，例如 `frames: [3,4,5,3]`。`loop: false` 表示播放后停在最后一帧。`cells` 可为每个物理格子指定 `{x,y,width,height}` 像素矩形，解决生成图行距不等的问题；长度必须等于 `columns × rows`，矩形不能超出图片。

`bakedProps: true` 表示食物或积木已经画在姿势中，程序不再叠加同类物品。旧版 `hands` 数组仍可读取；1.2.0-preview.7 的玩球改为身体命中／落空，不再把球固定在手部。

`heightRatios` 按物理格子指定相对站姿的可见身高，长度为 `columns × rows`，取值 0.15–1.5。例如坐姿 0.60、蜷起 0.49、侧躺 0.34。绘制时先校准参考身高，再应用这个比例，避免把坐姿或卧姿拉大到站姿高度。新增语义动作包括 `listen`、`land`、`build`、`ball-ready`、`anticipate`；它们同样遵循当前服装优先规则。

程序会校准这些姿势的可见身高与脚底，不再对已绘制的手臂做骨骼扭曲。减少动态效果时停在所选序列第一格，仍保留当前服饰。

Preview 10 的图集最多 6 列、6 行、24 个物理格子，播放序列最多 48 项。Q 版泳装与婚纱的日常动作同样使用独立逐帧图，不会切回原装或其他画风。

`isolateCells: true` 配合 `cells` 时，渲染器按连通轮廓分配像素，排除矩形中相邻角色的碎片。`separationAlpha` 是识别实心轮廓的起始透明度，默认 48，可用范围 16–240；仅在细发丝相连时提高。识别后向半透明边缘扩展，保留原色和透明度，不修改源图，也不能用来修复实心部位重叠。

`referenceHeightPixels` 可指定图集中参考身高的原始像素数，默认 0（沿用原来的 `heightRatios` 规则），大于 0 时优先按这个像素高度与当前服饰的基准立绘校准。这样每帧裁切框不同也保持相同的像素缩放倍率，卧姿自然变矮，头部不会突然放大。值必须有限且介于 0–6144。与 `heightRatios` 同时提供时，此字段优先。

## 真人舞蹈底图

Preview 13 的 `dance` 动作必须在当前服装中提供独立底图和 `danceRig`，不会回退到待机立绘或另一套服饰。该能力只向内置真人系列开放。底图为双脚不交叉、脚底同高、手臂向外自然放下的正面姿势；关节数据必须针对该服装测量。

`danceRig.joints` 是 17 个 `{x,y}` UV 坐标，均相对当前物理格的裁切区域，按以下顺序排列：骨盆、颈、头，画面左肩／肘／腕，画面右肩／肘／腕，左髋／膝／踝，右髋／膝／踝，左脚底、右脚底。`waist`、`hem` 是腰线和裙边的 UV 高度，`skirtWidth` 是半裙宽。可选 `clothWidths` 为从腰到裙边等距采样的 5 个半宽；高低裙可用 `frontHem` 与 `openingWidth` 保留中央露腿区域。

运行时使用 96×144 网格，沿不透明轮廓传播骨骼权重，为胸腹和衣料补充躯干控制范围，使透明空隙另一边的手臂不会直接拉动裙子。关节驱动为 8000 ms／16 拍，脚底分别固定和抬起，正面屈膝采用轻微缩短投影，避免左右扭膝。绘制随画面刷新推进，开始与结束以 220 ms 过渡接回同服装待机图。常态 Demo 使用相同渲染器导出完整 201 个时间采样。

若露肤手臂内侧与长发相连，可按图像高度设置 `armRadius`（0–0.05，默认 0）增加手臂实心控制范围；宽袖需保留默认值，避免把裙边带入手臂。此数值需逐服装校准，不能统一加大。
