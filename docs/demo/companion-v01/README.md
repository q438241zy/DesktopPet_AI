# 云朵伙伴 Demo

当前 **v1.10**：已批准的 v1.9 设计接入桌面原生程序，长期 HTML Demo 同步版本。八张伙伴卡独立随机预览，打卡与日程统一月／周历，陪伴日常分为动作与图鉴，会员收进设定分页，采用 Q版云朵宠物 Logo。见 [v1.10 原生验证与安装记录](../../verification-v110-native.md)；设计来源保留在 [v1.9 Demo 记录](../../verification-v19-demo.md)。

普通聊天使用简短问候，不出现行事历入口；独立行事历仍可整理事件。Claude Q版运动服正面稿已接入，可在 `claude-review.html` 对照原装、旧侧身与坐姿，图片没有程序变形。

Q版与3D真人均覆盖八位伙伴、四套服装，共64套外观；每 1–2 秒随机轮换站立、坐下、托腮、伸展和笑脸。图库时钟独立于当前桌面宠物，固定站坐偏好、聊天与互动不会锁住其他角色卡。桌面伙伴的自动动作不计为用户互动，也不推迟闲置一分钟躲藏。

「行事历」通过「记一件事」的专用输入整理事件与时间，确认后保存，到点由对应宠物笑着提醒；同一张月／周历显示打卡与补签记录。角色上方的聊天只聊天，两处历史分别保存。旧方案见[完整方案](../../pet-agenda-plan.md)。Demo 未接入 API 时只提供明确标注的固定演示，不假装理解任意记事输入。

v1.0 重要版本标签保留。本轮更新已有桌面程序与长期 Demo，不生成新的正式安装包。人物档案、工作模式、八家接口、服装与旧收藏保留；用户已保存的照片不删除。

站坐与多人合照的初次范围见 [v0.6 Demo 记录](../../verification-v06-demo.md)。当前仅使用已批准图稿，Claude Q运动服正面站姿已接入；部分其他 Q版服装仍为侧面站姿。站坐切换不代表新增连续起身动画。合照已从当前入口移除。

本页继续作为长期 HTML 预览，使用独立 Demo 存档，不会改动原生程序的宠物、账号、服装、日程或收藏。

## 打开与审阅

部署后打开 `Release/win-x64/Demo/CompanionV01/index.html`。桌面原有 `DeepSeek-動作Demo.lnk` 仍指向 CloudClub，顶部新增本页入口。

- 行事历：左侧入口，或 URL 加 `#agenda`。八位共享日程、记录负责提醒的角色；周/月查看、确认卡、修改/删除、提前提醒和单次/每天/工作日/每周重复。专用「记一件事」输入与普通聊天隔离，离开页面取消尚未返回的草稿；三个固定演示不调用 API。真实输入复用八家接口，至少思考一秒。
- 提醒：HTML 页面可见时按本机时刻触发，返回或重开时检查遗漏，已完成／10 分钟后结果持久化；预览不会改变真实日程。页面关闭时没有后台服务。原生使用独立调度，程序运行且宠物隐藏时也可提醒；原生与 Demo 存档分开。

- 我的伙伴：八位角色卡下方恢复原控制面板的卡片，原图等比显示，包含名称、风格、相处记录与原装/运动服/泳装/婚纱切换。不同角色、不同风格分别记住服装。右键角色卡片进入档案；“伙伴档案”按钮与 Shift+F10 提供等效入口。
- 图库预览：八张角色卡各自随机轮换五种姿态，不受固定站坐或当前伙伴动作/草稿影响；“暂停预览”只暂停图库。Demo 页面不可见、全局暂停、减少动态及模态框仍会暂停，恢复后重新等待1–2秒。原生预览由伙伴面板自己的计时器驱动，隐藏桌面宠物不会冻结八张卡；离开我的伙伴、最小化或关闭面板、模态对话框和减少动态时暂停。
- 当前伙伴待机姿态：卡片下方选择“自动 · 1–2秒 / 站立 / 坐下”。自动轮换站立、坐下、托腮、伸懒腰和笑脸，每次间隔随机 1–2 秒，不连续重复，轮到当前之外的另外四种才重新抽取。每位角色分别记住模式，Q版与3D真人共用模式。暂停陪伴、减少动态、页面隐藏或对话框停止轮换，当前互动、菜单、聊天草稿与待确认日程优先。恢复后重新等待 1–2 秒，固定站/坐不轮换。自动动作不计为用户操作，不推迟一分钟躲藏。全身采用本套服装原有帧及共同脚底基线、固定显示尺度，没有局部拉伸；伸展完整八帧按本次间隔播放。站坐之间仍为姿态切换，没有新增连续起身落座图。
- 档案：我们的默契、风格预览、说明三个分页。“说明”介绍人物个性、四项喜好和相处方式，不展示模型指令；Q版与3D真人共用说明和角色记录。每个角色分别记录 −100 至 +100 的关系值和可见页面上的陪伴时间。
- 聊天：伙伴卡“聊聊天”、档案“和她聊聊”或左下角版本测试工具进入预览。输入框仍在角色上方。普通聊天使用纯文本 API，不带日程 JSON 合同；本机聊天也不因“提醒”等词转入行事历。两处历史分开，问候简短，回复前至少思考一秒。聊天仍为第一层菜单入口。
- 躲藏：在独立预览中默认闲置一分钟后触发，或点击“躲藏”；先走向随机边缘，再留在边缘等左键找到。右键只切换菜单，不返回。正在输入草稿、打开分页或对话框时不自动躲藏，主页原图卡也不会自行走开。
- 设定：工作模式默认关闭，开启开关后才显示设置并按已保存间隔计时；间隔 1–180 分钟，默认 10 分钟，修改后点击“保存间隔”。无须填写提醒内容，八个角色各六种预设话语轮换；模型已设置且本次会话有 Key 时自动生成简短提醒，等待或失败期间仍使用预设话语，并标明实际来源。关闭开关同时停止计时、撤下提醒、取消未返回请求；试提醒不改变周期。重开页面时仅恢复开关与间隔，从完整新周期开始，不补发关页期间提醒。每轮使用当前人物笑脸；不会打断躲藏或聊天。暂停陪伴会暂停倒计时。浏览器关闭不提供后台服务。
- 行事历打卡：与日程共用月／周历，直接点击今天打卡，每日一次。已签日期可继续选择查看事项，未来日期可浏览。补签卡默认0，有卡时对过去漏签确认消耗1张；不补发好感或陪伴时间。保留连续／累计及月周偏好，跟随今天跨日时自动翻页，手动浏览历史时不跳回。顶端“记一件事”展开独立AI记事输入，真实输入需要API，固定演示仍明确标注。
- 陪伴日常：动作／图鉴收集两页，动作15项玩耍与12项互动，点击进入当前伙伴和服装的动作流程；图鉴含10球、6食物、4小物和10故事。礼物与读完的故事才计入收藏，旧记录保留，故事可重读。
- 设定分区：陪伴与提醒／AI接口／账号与会员。会员保留登录、注册分页的本机账号，随机盐与PBKDF2摘要、密码不存明文；Demo与原生账号分别保存，无新增付费或云端账号服务。品牌采用同一份Q版云朵宠物设计，原生窗口和16–256px应用／托盘图标由矢量源生成。
- 点击左下角版本号可使用“模拟闲置一分钟”“推进一个提醒周期”和当前角色关系值滑杆。只改变测试存档，不冒充真实陪伴时长。

## 已确认的本轮规则

八位角色的说明、喜好和口吻保存在 `personas.js`，同一份定义同时用于本机多轮对白和 API 提示词；询问喜好和自我介绍会按人物设定回答，换衣或切换画风不改变设定。这是桌面虚构人物设定，不是对应厂商或真实模型的个人偏好。每次回复至少思考一秒；慢接口持续等待到回复或 45 秒超时，错误不伪装成本机成功回复。切换角色、风格、接口或退出账号会取消旧请求。

好感暂按打卡 +3、有效聊天 +1、摸头 +1、共读 +2、礼物 +2、安静陪伴五分钟 +1 试行。正向每天上限 20，有交互冷却；十秒内连续摸头六次触发温和边界与 −2，最低 −100，最高 +100。漏签和关闭程序不扣分。服装门槛暂提议原装 0、运动服 20、泳装 50、婚纱 80，未达成显示笑脸小锁；**测试期所有风格仍开放**。这些数值属于本轮方案，未经用户拍板不得强制用于正式解锁。

原生保留后台提醒与旧存档读取，历史合照功能已在 v1.8 移除。角色工房、生成器附件和专用导入器已移除；用户以前导入的角色和存档不删除。

## 接口检查

Demo 支持 GPT/OpenAI、Claude、Gemini、Grok、DeepSeek、Qwen、GLM、Kimi 八家。Claude 使用 Messages，Gemini 使用 generateContent，其余使用各自官方 Chat Completions 格式。请求、鉴权、回包解析、端点和官方来源见 [八家接口核对](../../companion-api-providers.md)。界面可保存设置并测试连接，模型名由用户填写已开通的型号；示例仅作占位提示。API Key 只留在页面内存，切换服务或编辑地址清空输入，刷新后重新填写。模拟检查不能证明实际账号、额度、网络和浏览器跨域可用。

原生适配位于 `CompanionProviders.cs`，由 HttpClient 调用相同协议；人物设定从本 Demo 的 personas.js 导出为核心内嵌 JSON，避免说明与回答分叉。

- [OpenAI Chat Completions 官方参考](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)：`https://api.openai.com/v1/chat/completions`。
- [DeepSeek 官方入门](https://api-docs.deepseek.com/)：`https://api.deepseek.com/chat/completions`，也接受 `/v1` 基础地址。模型名称填写账号当前可用的型号。

自动检查截获请求并返回模拟回复，验证端点、消息角色、认证头、内容解析与思考时长；没有调用付费模型，也没有声称实际 API Key 已验证。浏览器直接访问用户填写的接口可能受 CORS 限制，错误有明确反馈；原生通过 HttpClient 请求，不受浏览器 CORS 限制；账号与实际网络连通性仍需真实配置验证。

```powershell
python tools/build-companion-demo.py
./tools/install-companion-demo.ps1
node tools/verify-play-preview.cjs
node tools/verify-simple-chat.cjs
node tools/verify-idle-variety.cjs
node tools/verify-companion-boundaries.cjs
node tools/verify-companion-providers.cjs
node tools/verify-unified-calendar-v19.cjs
node tools/verify-companion-layout-v19.cjs
node tools/verify-card-idle-v19.cjs --expect-independent

```

`data.js`、`idle-art.js` 和 `play-art.js` 由角色清单、原始图片、故事库与 `Version.props` 派生。所有原图像素不变，只生成位置、固定尺度和分格归属元数据；不再导出合照图像编码。当前预览图片缓存上限为 48 张。

验证脚本使用真正 Chromium file 页面、鼠标点击、键盘输入和 PNG 导出；计时长周期通过 Demo 时钟推进检查。v0.4 月/周历11组报告位于 `.artifacts/companion-v04-review`；回归脚本可通过 `COMPANION_REVIEW_DIRECTORY` 指定报告目录，检查前后核对日常 exe 和 state 文件哈希。补签测试的卡片仅注入隔离浏览器上下文，不修改用户存档。八家请求由测试路由截获并回包，不使用真实付费密钥。

公开展示使用隔离浏览器或独立存档的原生测试实例，仅渲染Demo页面、应用自身窗口或历史合照画布，不截取桌面、任务栏或其他应用。v1.10原生截图位于 `docs/images/v1.10`，日程、打卡与陪伴均为测试数据，账号字段为空。
