# 从任务栏提起与主动上移 · Demo 后实施计划

2026-09-30 先完成离线 [交互 Demo](../Release/win-x64/Demo/TaskbarLift/index.html)。可从桌面 `DeepSeek-動作Demo.lnk` 打开的动作页进入，也可直接打开 `Release/win-x64/Demo/TaskbarLift/index.html`。页面可切换 Q版、3D真人及三套服装；素材从当前常态 Demo 的真实渲染帧抽取，仅引用 23 张现有无损图，没有添加新图片副本。三个示范按钮分别演示快速抓起、慢慢摆放和半空接住。浏览器画面中的任务栏为模拟区，原生宠物的拖动逻辑尚未改变。

现状：`PetWindow.BeginLift()` 已在开始拖动时判断是否来自工作区底边，`ReleaseLift()` 却直接清除此标记并固定在松手位置。`DropToFloor()` 只在后续散步等自然动作中使用。因此要改的是**松手判定**，保持鼠标按住期间完全跟手，不能让重力和拖动同时争夺窗口位置。

| 起手与手势 | Demo 松手结果 |
|---|---|
| 从任务栏提起不足 24px | 留在任务栏 |
| 从任务栏快速提起约 150px、不到 900ms，未停留 | 松手后自然下落，落地缓冲 |
| 在半空停留至少 450ms，或按下至松手达到 900ms | 固定在新位置，保存坐标 |
| 快速移动时按住 Shift 松手 | 明确固定，避免相同鼠标轨迹无法辨认意图 |
| 从已抬高的位置重新抓住、下落中再抓住 | 新手势按主动摆放处理，松手后不继续下落 |

这是一组供试看的初始阈值，不假称可以读出用户意图：**完全相同的快速向上拖放轨迹本身无法区分“想抛起”与“想放高处”**。停留、抓住较久和 Shift 是 Demo 提供的明确区分方式；页面会在松手前显示预计结果，最终阈值应以手感复核。

实施原生版时分四步：

1. 在 `PetDown`/`BeginLift` 锁定起手屏幕、工作区底边和初始位置。沿用现有 DPI 转换与当前显示器 `WorkArea`，只在提起起点判定一次是否在任务栏；开始于半空不继承此前的底部来源。
2. `PetMove` 保持当前位置跟随鼠标，记录位移、经过时间和最后一次明显移动时间。`PetUp` 调用一个可单独测试的决策函数，优先处理按 Shift 固定、明确停留与持续慢移；晃动触发头晕时沿用既有原地恢复，不意外落下。
3. 只有符合快速提起条件时进入 `DropToFloor()`。下落帧按实际位置推进，允许再次抓取中断；触地只播放一次缓冲并保存一次最终坐标。主动上移直接保存当前位置，之后不得由一般计时器自动掉回底部。减少动态效果时直接完成落地，不强制播放重力动画。
4. 对齐现有原装、泳装、婚纱动作。3D真人先沿用专用提起与落地姿势；当前 Q版婚纱的提起末帧在半空看起来仍像坐姿，接入原生前应补更明确的悬空姿势及落地缓冲帧。不能借用另一套服装的图片。

原生验收应覆盖 Q版/3D真人 × 三套服装，快速松手、缓慢上移、半空停留、Shift 固定、低于阈值、晃动后松手、下落中重抓、窗口失焦与多屏幕/DPI。旧存档位置和打卡信息不变；测试只用独立 `--data-dir`。浏览器 Demo 的阈值与落点已过 133 项逻辑/素材检查，Chrome 实际渲染检查了快速下落、固定、半空重抓和 Q版婚纱画面。当前只交付 Demo 与计划，不声称原生行为已改变。
