# Preview 18：动作切换尺寸

2026-10-02，处理两类缩放错误：历史 Q版动作中间帧本身被画小；新积木坐姿及部分日常动作又按轮廓高度、姿势比例逐帧缩放。

历史 Q版以头发／脸部纹理相似变换测量源图比例，写入 `frameScaleFactors`。新积木和 3D真人图集使用固定 `referenceHeightPixels`，以基准姿势维持同一像素比例；原图、分辨率和透明度不变。坐卧保留降低的姿势高度，不把躺卧拉到站立大小。进食的手、食物和身体保持同一比例，舞蹈仍使用各服装的专用骨骼底图。

修正前后，240 逻辑像素设置下 DeepSeek Q版原装的可见高度如下。高度用于记录观察，不代表所有姿态必须相同；跳跃图有展开的手臂，提起图的腿也会伸直。

| 动作 | 修正前 | 修正后 |
|---|---:|---:|
| 待机 | 184.2 | 184.2 |
| 堆积木 | 140.0 | 181.5 |
| 跳跃中间姿态 | 138.3 | 212.2 |
| 思考中间姿态 | 157.5 | 196.0 |

`--verify-scale` 在独立数据目录检查全部 48 套外观：切换动作不改变用户尺寸、脚底／离地基线、图集像素比例、120 与 300 尺寸下反复返回待机不累计缩放。输出 DeepSeek、GPT 的两种风格三套服装渲染图和逐动作测量 JSON。姿势截图来自 WPF 自身渲染器，不是生成概念图。

源画仍可能有表情、透视或人体比例差异，尺寸元数据不能把这些画稿差异修成同一张脸。开发版与发布版的检查结果及常态 Demo 更新记录见本文件后续验证记录。
