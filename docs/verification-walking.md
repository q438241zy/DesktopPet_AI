# Preview 12：散步流畅度

2026-09-28，修复桌面散步的间歇停格、位置取整误差和边缘转身的步伐跳变。覆盖八位角色、Q／3D／真人三种风格及原装／泳装／婚纱。

## 原因与修改

旧实现用 16 ms 的 DispatcherTimer 触发移动，但本机实际位置更新的中位间隔是 30–33 ms；不少画面刷新仍显示上一位置。窗口位置还会取整到物理像素，下一步再读取该位置积分，使走路速度偏快，图片里的脚步和身体位移逐渐不一致。

- 散步及走向边缘躲藏改由 `CompositionTarget.Rendering` 驱动。同一次画面刷新仅推进一次，结束、隐藏、关闭及切入离线预览时解除订阅，待机继续使用低频计时器。
- 逻辑位置保留小数。窗口移到整物理像素，余量交给画面内的平移，位置取整不再累积到下一步。
- 脚步进度按实际行走距离推进。一般延迟帧保留完整行走时间；超过 250 ms 的中断限制单步推进，避免系统恢复后大幅跳位。球和掉落仍使用原有物理步长。
- 到边缘时保持到达当下的姿势，停稳 160 ms 再转身；转身完成后的剩余帧时间继续行走，不强制切回第一张图。
- Demo 同步连续位置、延迟帧和边缘转身的处理；动作清单注明连续移动方式。

这次修改移动调度与步伐同步。美术仍为每套外观 12 张独立姿势、960 ms 循环；没有把画面刷新次数写成新增美术帧数。

## 本机前后实测

在 125% Windows 缩放下，使用隔离存档，分别记录三种 DeepSeek 风格的 2.4 秒直线散步。数据来自原生 WPF 的画面回调及窗口位置，不是网页模拟。排除启动和首次解码的 400 ms。

| 风格 | 修改前位置更新中位间隔 | 修改后 | 修改前位置重复的回调 | 修改后 |
|---|---:|---:|---:|---:|
| Q | 31.38 ms | 16.68 ms | 44 / 108 | 0 / 144 |
| 3D | 30.42 ms | 16.64 ms | 43 / 111 | 0 / 143 |
| 真人 | 33.25 ms | 16.72 ms | 49 / 115 | 0 / 144 |

三种风格移动距离原先分别比设定速度快约 11.3%、7.8%、8.2%；修改后与按实测时间计算的目标距离相差均小于 0.12%。这是本次机器状态下的量测，不代表所有设备的固定帧率，也不等于操作系统最终呈现画面的录像。

原始记录位于 `artifacts/walk-before/walk-timing.json` 与 `artifacts/walk-after/walk-timing.json`；便于随发布包查看的摘要见 [量测数据](walking-timing-summary.json)。可用 `--verify-walk --data-dir <独立目录>` 重复记录三种风格并验证全部外观。
